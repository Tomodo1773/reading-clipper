# ADR 0032: 新着一覧をやめ、閲覧ページを在庫の面にする

- ステータス: Accepted（読み取り専用の判断は[ADR 0033](0033-dismiss-clips-from-the-web-page.md)で更新）
- 日付: 2026-08-31

## 背景

[ADR 0017](0017-generated-recent-clip-index.md)は`clips/README.md`を「最近保存した20件」の派生ビューとして作った。出発点は「GitHubのフォルダが名前順なので、最近保存した記事がどこにあるか分からない」ことで、あれは*新着*の面である。[ADR 0023](0023-clip-index-cards-and-dismissed-marks.md)がカードと片付けの印を足し、[ADR 0030](0030-read-only-clip-page-on-the-public-boundary.md)が同じ母集団のまま閲覧ページ`/clips`を足した。

運用してみると、あの一覧を開く目的は新着の確認ではなく、**まだ片付けていないものを見ること**だった。そして今の作りでは、それができない。

- 母集団は「保存の新しい順20件」で、**片付け済みもその20件の席を取る**。片付けは表示側で振り分けるだけで、母集団は絞っていない（ADR 0017、ADR 0023）。
- 1日3件の保存ペースでは窓がおよそ1週間になる。**それより古い未片付けのクリップは、原理的に一覧へ出てこない。**
- 見出しには「まだ片付けていない M件」と出る。**数は見えるのに、その中身は見えない。** 直近20件がすべて片付け済みなら、未片付けは1件も表示されないまま数字だけが残る。

ADR 0030は、この疑問を「本当に見たいのは最近の20件ではなく、片付けていない在庫のほうではないか」として明文で保留し、変えるならGitHub版と一緒に変えると書いた。その保留を開ける。

「片付けたものも見たい」という要求は別にある。読み終えた記事のURLを職場へ共有したいときに、閲覧ページを開いて取りに来る、という使い方である。これは*眺める*ではなく*特定の1件を取りに来る*動きで、必要なものが違う。

## 決定

### 閲覧ページを、役割の違う2段にする

- **上段「まだ片付けていない」: 未片付けを全件。** サムネイル、抜粋、ホスト、保存日を添える。眺めて選ぶ面なので、思い出せる材料を残す。
- **下段「片付けたもの」: 片付け済みを全件。1行だけ。** 題名のリンク、保存日、ホスト、保存済みMarkdownへのリンク。**サムネイルと抜粋は出さない。**
- 並びは両段とも`clipped_at DESC, path ASC`で変えない。
- 取り消し線と薄字は廃止する。見出しで分かれる以上、同じことを二重の印で言わない。
- 件数は見出しへ入れる（`まだ片付けていない（12件）`）。全件を描くので、節の長さがそのまま件数になる。数える問い合わせを別に持たない。
- 上段が0件なら「全部片付いた。」と出す。下段が0件のうちは節そのものを出さない。両方0件なら「まだクリップはない。」だけ。

### 件数の上限を置かない

窓で切ることが、そもそも今回の不具合の原因である。上段を切れば在庫が見えなくなり、下段を切れば「あの記事」が窓の外にある確率が残る。

**下段を1行にしたのは、上限を持たずに済ませるための条件である。** ページはスクリプトを持たない1枚のHTMLなので、全件がそこにあればブラウザのCtrl+Fが効く。特定の1件を取りに来る面としては、これが最も強い。

1件あたりおよそ400バイトで、数百件でも数百KBに収まる。[ADR 0031](0031-list-clips-from-the-file-tree.md)が`list_clips`の100件を「ガードではなく機能上限であり、有限の寿命を持つ」と書いたのと同じ性質の見積もりである。**将来この量が問題になったとしても、戻すべきは件数の窓ではない。** 窓は在庫の面を壊す。畳むなら年でまとめるなど、在庫が全件見えることを保ったまま考える。

### `clips/README.md`の自動生成を廃止する

閲覧ページが全クリップを載せる以上、GitHub版に残る役割が無い。

- ADR 0017が解こうとした「フォルダが名前順で新着が分からない」は、閲覧ページが引き取る。しかも閲覧ページはGitHubへログインできない環境からも開ける（ADR 0030）。
- 記事の保存・削除・翻訳・片付けのたびに走っていたREADME更新のコミットが、すべて無くなる。
- 連続した片付けで起きていたSHAの競合と、そのための再試行（ADR 0023）が要らなくなる。
- ADR 0030が「片方だけ範囲を変えると、同じ名前の一覧がGitHubとWebで食い違っていく」として範囲を揃えたが、**片方が無くなれば揃える相手がいない。**

保存先リポジトリに既にある`clips/README.md`の実ファイルは、生成を止めても残る。更新されなくなるだけで害が無いため、消すかどうかは運用の判断に委ねる。

### 所有マーカーをやめ、パス一致で母集団から外す

ADR 0017は、生成したREADMEに所有を示すコメントを入れ、「手書きREADMEや過去に同名で保存された記事を、名前だけで黙って除外しない」と決めていた。生成をやめる以上、そこにあるのは手書きのREADMEだけであり、区別する相手がいない。

`makeClipFileName`は題名`README`を`README-clip.md`へ逃がすので（`src/url.ts`）、**`clips/README.md`が記事であることはない。** 所有マーカーという概念ごと落とし、パス一致で外す。

この判断は`src/github.ts`の`CLIPS_README_PATH`に置く。バックフィルは同じ判断をNode側に持つ。**あちらは素のESMで走るため、拡張子の無い相対importを持つモジュールからは読めない**（`src/excerpt.ts`と`src/html.ts`に「何もimportしない」制約が課されているのと同じ理由）。文字列が2か所に散ることを受け入れ、実行環境をまたぐ依存を増やさない。

### 抜粋と並び順は今回変えない

- 抜粋は本文の先頭100文字のままにする（[ADR 0011](0011-digest-rows-with-excerpt-and-thumbnail.md)）。短すぎて役に立っていないという問題は残るが、それは「何を材料にするか」の話で、この一覧の母集団の話とは別に決める。
- 上段は保存の新しい順のままにする。**古い在庫が下へ沈むことは残る。** 週次ダイジェストは飢餓を避けるために提示の古い順で選んでいるが（[ADR 0010](0010-weekly-digest-and-dismiss-bit.md)、[ADR 0018](0018-verify-clip-exists-before-digest.md)）、棚に同じ仕掛けを入れるかは、まず全件が見える状態で運用してから決める。
- 読み取り専用のまま。片付けのボタンは置かない（ADR 0030）。

## 検討した代替案

- **窓を20件から広げるだけ**: 最も小さい変更。ただし在庫の量は片付け次第で変わるので、どの数を選んでも「片付けていないのに見えない」が確率的に残る。原因は数ではなく、状態で切るべきものを時間で切っていることにある。
- **片付け済みを完全に落とす**: いちばん単純で、実際に最初はこれで足りるという感触もあった。ただし読み終えた記事のURLを取りに来る使い方が実在し、そこが空になる。加えて、片付けた結果が表示に出ることは片付けが効いている手応えでもあり（ADR 0023の出発点）、件数の数字だけになると薄くなる。
- **下段を件数で切る（直近20件など）**: ページは短く保てる。ただし探している1件が窓に入っているかどうかが運になり、Ctrl+Fで確実に当たるという下段の値打ちが消える。1行にすれば切らずに済む。
- **下段を「片付けた順」に並べる**: さっき読み終えたものが上に来るので、共有の用途には合う。採らないのは、下段に全件あってCtrl+Fが効く以上、順番がほとんど効かないため。並びと表示日付を段ごとに変える必要も無くなる。
- **GitHub版を残し、範囲だけ揃える**: ADR 0030の判断を保てる。ただし同じ材料から2つの一覧を作り続けるコスト（保存のたびのコミット、SHA競合、Markdown用の描画とテスト）を、閲覧ページが上位互換になった後も払い続けることになる。
- **GitHub版だけを在庫の面に変え、閲覧ページは新着のままにする**: 逆方向。GitHubへログインできない環境で開けないほうを在庫の面にする理由が無い。

## 影響

- **保存・削除・翻訳・片付けのたびのGitHubコミットが無くなる。** 片付けボタンの反応も、GitHubへの往復が消えるぶん速くなる。
- `clips/`をGitHubで開いても、新着は分からなくなる。名前順のファイル一覧だけが並ぶ。閲覧ページが全件を担うため許容する。
- **ページの高さが保存件数に比例して伸びる。** 上段は片付け次第、下段は単調に増える。下段は1行なので、伸びてもスクロールとCtrl+Fで扱える範囲に留まる。
- 未片付けが多いと、上段のサムネイルがその件数ぶん並ぶ。`loading="lazy"`が効くので、表示されるまで取りに行かない。
- 手書きの`clips/README.md`を置いても、記事としては扱われない。ADR 0017が守ろうとした「名前だけで黙って除外しない」は失うが、除外されて困るものが存在しない。
- `clips/README.md`の生成に使っていたMarkdownの描画（カード、箇条書き、取り消し線）とそのテストが無くなる。表示形式はHTMLの1本だけになる。
