# ADR 0029: ダイジェストと新着一覧から全クリップのGitHub版へリンクする

- ステータス: Accepted（`clips/README.md`への副リンクは[ADR 0032](0032-clip-page-shows-the-backlog-not-the-newest.md)で廃止。週次ダイジェストと閲覧ページの副リンクは継続）
- 日付: 2026-08-31

## 背景

日本語でない記事は保存後にGitHub上の本文が日本語へ置き換わるようになった（ADR 0027）。
一方、週次ダイジェストと`clips/README.md`の題名は元記事だけを指すため、訳文を読むには
リポジトリ内で同じ記事を探し直す必要がある。

## 決定

- 題名のリンク先は元記事のままにする。出典へ戻る主導線は変えない。
- Slackの週次ダイジェストでは、実在確認のContents APIが返した`html_url`を使い、題名の横に
  「GitHub版」の副リンクを置く。確認に失敗した週は、誤ったURLを組み立てず副リンクだけを省く。
- `clips/README.md`では、カードと箇条書きのメタ情報に、同じディレクトリからの相対リンクで
  「GitHub版」を置く。表示中のブランチやコミットをそのまま保つ。
- 翻訳済みだけでなく、保存されている全クリップに出す。ただしURLの無いダイジェスト行は、
  題名自体がGitHubを指しているため重複させない。

翻訳済みだけに絞るには、フロントマターの`translated_at`をD1へ複製し、翻訳・再保存・
バックフィルの各経路で同期する必要がある。表示を減らすためだけに新しい派生状態を持つより、
「保存版を開く」という一貫した意味で全件へ出す。これにより、元記事が消えた場合にも同じ導線が使える。

## 検討した代替案

- **翻訳済みだけに出す**: 日本語版があることは明確になるが、表示のためにD1の列と移行が増え、
  翻訳失敗や再保存との同期も必要になる。
- **題名をGitHub版へ向ける**: 1リンクで済むが、出典へ直接移動する従来の使い方を失う。
- **GitHub版だけを出す**: 保存した本文を読む用途には合うが、公開元の最新内容やコメントへ戻りづらい。

## 影響

- 各クリップにリンクが1つ増える。
- GitHubの既定ブランチ名を設定として持たない。SlackはGitHubの応答、READMEは相対位置から
  保存先を決める。
- 「GitHub版」は翻訳済みを意味しない。日本語記事や翻訳に失敗した記事では保存時の言語のままである。
