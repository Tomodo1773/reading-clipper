# ADR 0013: クリップの保存先をホストごとのフォルダから外し、フラットにする

- ステータス: Accepted
- 日付: 2026-08-17

## 背景

ADR 0005で保存先を `clips/{host}/{記事タイトル}.md` と決めた。ホストごとにフォルダを分けたのは、ファイル名衝突の単位を「同一ホスト内」に絞るためだった。

実際の使い方では、ホスト単位でクリップを見返す場面はほとんど無く、ファイル名を手がかりに全体を横断して探す場面のほうが多い。ホストフォルダは、その探し方の妨げにしかなっていない。

## 決定

- 保存先を `clips/{記事タイトル}.md` にする。ホストごとのサブフォルダは作らない。
- ファイル名衝突時に上書きする方針（ADR 0005）はそのまま引き継ぐ。衝突の単位が「同一ホスト内」から「`clips/` 全体」に広がる。
- 週次ダイジェストのメタ行（`clipHost`）が表示するホスト名は、これまでパスの第2セグメントから取っていたが、`clips` テーブルの `url` 列（記事のcanonical URL）から `new URL(url).hostname` で取る。`url` が無い行（バックフィル由来など）はホストを出さず、保存時期だけを出す。
- `schema.sql` の `path` 列コメントを実態に合わせて更新する。列の追加ではないため `ALTER TABLE` は不要。

## 検討した代替案

- **ホストフォルダを残し、D1やUIの一覧をフラットに見せる**: 見る場所を増やさずに済むが、GitHub上でファイルを直接見返す・検索する使い方そのものがフラット前提なので、保存構造とずれたままになる。
- **ファイル名にホストを埋め込む（例: `{host}-{タイトル}.md`）**: 衝突の単位が変わらず、ファイル名が長くなるだけで、フォルダを無くす動機（横断して探したい）に応えない。

## 影響

- **衝突の単位が広がる。** 異なるホストの記事でもタイトルが一致すれば上書きされるようになる。元々「同一ホスト内でも上書きを許容し連番やハッシュを足さない」方針（ADR 0005）だったため、方向としては連続した変更である。
- **既存ファイルは移動しない。** この変更は新規保存以降のパス決定だけを変える。GitHubリポジトリに既にある `clips/{host}/...` は、そのタイトルで再クリップされない限りそのまま残り、D1の `path` 列も古い値のまま参照し続ける。しばらくはネストしたパスとフラットなパスが混在する。
- 週次ダイジェストのホスト表示が、保存先パスではなく実際の記事URLから決まるようになる。ホストフォルダに依存しなくなる一方、`url` を持たない行はホストの表示を失う。
